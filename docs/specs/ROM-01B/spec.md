## Outcome and scope

An authorized editor can safely deactivate/reactivate a room, remove a provably unused new draft, and understand refusals. Internal viewers can inspect a room's active-term weekly bookings and potential gaps with meaningful utilization and uncertainty labels. All new room assignments use guarded choices and authoritative server checks.

Included: lifecycle controls on room details; all-term lifecycle/deletion evidence; persistent draft-retention marker and populated migration; atomic revision/audit handling; narrow integration with every room-reference writer; directory status filters; room weekly agenda and free-window filters; one shared screen/print occupancy calculation; responsive workflow sketches and adapter/race/browser verification.

Excluded: ROM-01C dated maintenance/unavailability and its placement/conflict integration; real-date free-room promises, calendars/holidays/cancelled occurrences; broad scheduling/publication concurrency changes; term selection/activation; automatic reassignment; room merges/import/export; source reconciliation; historical directory versions; hosting and institutional migration. #5 stays open after this slice. No CSV export is added; existing routine CSV/official/public projections must remain unchanged.

## Required behavior

### Lifecycle and evidence

Use `/rooms/[id]` for status and editor-only Deactivate/Reactivate controls. Status changes take room ID, expected positive integer revision, explicit target action and a required plain-text reason (trimmed, 1–300 characters). Validate runtime types, duplicate/ambiguous scalar fields and allowed actions; malformed or forged requests cannot become a different action. Keep entered reasons on refusal. Permissions are checked on every server entry point before protected reads/writes.

Lock the room before reading fresh reference evidence. Wrong revision returns the existing stale result and a deliberate reload action; missing/deleted room returns missing. Same-state repeated action returns a truthful no-op with no audit or revision change. No successful status change can be claimed on a failed transaction. Directory edits continue to work on inactive rooms and preserve status/draft retention.

Deactivation reference query joins every meeting-room role through the teaching group to its term, without active-term filtering. For each active meeting:

1. Read one server date `today` in Asia/Dhaka for the attempted mutation; do not accept a client clock.
2. Calculate `L = max(today, term.startDate, meeting.effectiveFrom when set)` and `U = min(term.endDate, meeting.effectiveTo when set)`.
3. If valid bounds have `L > U`, there is no future use. Otherwise block if at least one date with the meeting's academic weekday (0 Saturday … 6 Friday) lies in inclusive `[L,U]`. Compute dates without host-time-zone/local-DST arithmetic. Invalid/inverted source date ranges, missing term joins or malformed weekdays fail closed with identifiable records; do not silently treat them as past.

Cancelled/inactive meetings do not block deactivation; their references still prevent deletion. Future/current terms count regardless of term status. Duplicate room rows/merged audiences count once per canonical meeting, with all assigned roles retained in evidence. Report term, course/audience, weekday/time, effective bounds and first blocking date. Paginate large evidence lists; show full totals, never gate on only the first page. Existing active-term links may not open old-term classes; identify them by term/record without implying a term-switch feature.

For **any OD record referencing the room**, intersect `[today, term.startDate … term.endDate]`. Expired terms do not block. A complete valid weekday/time blocks when that weekday occurs in the remaining interval; missing/invalid timing, unknown kind or unresolved room-associated notes block as unverified use while the term is non-expired. OD has no dated effective range or inactive flag: do not invent either, infer expiry from verification status or fabricate teacher conflicts. Offer the OD register where applicable and say what needs correction/removal. Frozen publications alone do not block deactivation.

On success set `isActive`, increment revision exactly once and atomically add `room.deactivate` or `room.reactivate` with stable room ID, actor, reason, previous/new status and revision. Reactivation needs no booking-fit certification; it restores eligibility subject to ordinary capacity/capability/conflict checks. Existing protected identities may be deactivated safely, but cannot be deleted or lose their protected facts. Inactive identity/code remains reserved.

### Permanent deletion and retention

Add a forward-only non-null boolean `isDraft` with database default `false`. Backfill **every** existing room as retained without guessing from incomplete audits. Only portal create explicitly writes `true`. Do not expose the marker as an editable checkbox, release a retained room back to draft, or permit a user-supplied marker. The UI explains “Never assigned draft” or “Retained record”; this does not certify source approval or publication status.

On first successful manual create/update, automatic batch application, or OD insertion that refers to a draft room, consume draft status (`false`), increment the room revision and record one atomic `room.retain` event explaining first assignment. Failures/no-ops and cancelled transactions must not consume the draft. Keep the existing meeting-first/sorted-room lock order, lock all involved room IDs before any suitability/reference read, and do not acquire more room locks out of order. Test both orderings against lifecycle/delete/editor actions. Later deletion of the class/OD does not restore draft eligibility. New imports default retained. Inventory any additional reference writer before implementation; newly discovered unguarded writers must join this narrow contract.

Delete only when all of these fresh conditions hold under the room lock: expected revision matches; marker is draft; identity is not source-protected; no meeting-room reference of **any status, role or term**; no OD reference of any kind/term; no persisted snapshot reference in any schedule-version state. Recognize supported legacy/current snapshot shapes by room ID and structured code references, including prior codes from this room's audit history; unknown/malformed potentially relevant snapshots fail closed. No broad text substring match that confuses `ROOM-1` with `ROOM-10`. Snapshot defense supplements the monotonic retention rule; this work does not fix BUG-25 publication version races.

Show a dedicated confirmation with room code, retained/draft status, reference totals and irreversible outcome. Require typing the exact canonical room code and a trimmed 1–300-character reason, in addition to the expected revision. Active or inactive unused drafts may be deleted. Refusals explain why and suggest deactivation when appropriate; an already missing room gives a missing result, never a second success. Do not cascade, null references, recycle IDs or delete audit history. Add `room.delete` atomically with before-values/reason/actor/ID; retained audit rows remain even though the detail route becomes not found. Return to `/rooms` with contextual success. An unused deleted code can be reused by a new room with a new ID; an inactive retained code cannot.

### Guarded room choices

Keep all room rows in read projections needed for historical display; do not globally hide inactive rooms in `getPortalData` or serialized snapshots. Directory supports Active (default), Inactive and All, with visible counts and stable room-code sorting. Search matches code/building; invalid status filter falls back to Active with a comprehensible state. Preserve filter/search on return from detail or successful lifecycle action where possible. Zero results differs from an empty directory. Print reflects the displayed filter and names it.

Inventory builder create/edit, drag/move, “where it fits”, manual action, auto suggestion/apply and OD new-room choices. Offer only active candidates and reconcile picker suitability with ROM-01A's accepted independent lab-type/required-capability checks. Unknown capacity/count stays unknown and produces the existing warning; do not invent seats or silently change institutional rules. Busy status remains explained through existing conflicts. Selected inactive rooms are visible in an edit panel with code/status and instructions to replace/remove; they are not offered for other assignments. A missing selected room shows an explicit unavailable item rather than disappearing.

Recheck room existence/activity after locks in every assignment writer, particularly OD insertion. Reject stale cached choices with a standard plain result, keep entered OD/class data and permit refreshing choices. No exception note or warning acknowledgement can bypass inactivity. Multiple-room and automatic batch saves remain all-or-nothing, preserving roles and existing audit behavior. Lifecycle success refreshes affected room, OD and builder paths after commit using installed Next.js guidance.

Drag, keyboard move, undo and time-grid bulk “move classes” must also lock affected meetings and their currently assigned rooms, then check room activity before applying the move. For a multi-meeting operation, acquire **all affected meeting locks in ascending ID order, then the sorted union of room locks**, before suitability checks or writing any move; re-read the assignments after meeting locks and before taking the room union. Do not implement a loop that takes a new meeting lock after already taking room locks. Refuse the whole operation with the original placements/grid intact if an affected room is inactive/missing. This prevents weekday changes from resurrecting future use after deactivation; broader move/conflict concurrency repair remains excluded.

### Weekly occupancy and free windows

Add “View weekly occupancy” at `/rooms/[id]/occupancy`, linked from the directory/detail; directory summaries reuse the same pure projection. Show active term, room status/type/capabilities/seats, “Weekly planning pattern”, calculation basis and generated-at timestamp in Asia/Dhaka. Show seven academic weekdays Saturday–Friday, with exact-minute agenda rows for canonical classes and timed `room_reservation`/`combined` OD bookings. Every primary/alternative/segment assignment reserves the full stored interval until a future approved segmentation model exists. Merged classes count once per room. Display effective ranges as annotations and warn that this projection combines the term's active weekly records without resolving actual dates. No mutation/book button is added to a free gap.

Use half-open `[start,end)` intervals: adjacent bookings do not overlap; union overlaps and touching intervals for occupied/free calculations. Distinct event counts remain distinct from union minutes. Deduplicate `(meetingId,roomId)` before projecting. Pending-verification OD reservations with complete times still reserve recorded time. Outgoing-teaching metadata alone is not a room-reservation interval; show it as associated information. Partial/invalid/unresolved room-associated OD records appear in a separate uncertainty list and do not create fake times, negative durations or zero-minute “confirmed bookings”. Missing day affects the whole week; known day affects that day. Potential gaps on affected days carry “Unverified booking data”; do not label them confirmed free.

For each weekday and stream, start with applicable global/active-term **stream-wide** permitted windows and subtract the union of that stream default pattern's `blocksClasses` breaks. No stream plan/closed day supplies no common usable interval; missing pattern or malformed windows produces a configuration warning and no free claim for the affected scope. Union the remaining stream intervals. Batch-specific windows/plans do not widen/shrink the common baseline. A break affecting HSC only is still usable by Diploma if its own rules permit it. Explain this common planning denominator; it is not a selected audience's scheduling permission.

Compute and label separately:

- **Recorded booked minutes:** union of all valid class/reservation intervals, including portions outside common windows.
- **Booked within common windows:** intersection of booked union and common-window union.
- **Common usable minutes:** length of common-window union.
- **Utilization:** booked-within/common-usable, rounded for display; show “Not configured” when denominator is zero. Text and bars use this same denominator (0–100%).
- **Potential gaps:** common-window union minus booked union, with uncertainty flags. Inactive rooms show historical/planning occupancy but no assignable free-window results. Out-of-window bookings remain visible with their separate minute total.

Show capacity/capability alerts using accepted room-fit rules and existing audience semantics (deduplicated merged audiences, unknown counts explicitly unknown); do not let unrelated conflict alerts disappear. For a free-window search, filter day (All or a valid academic weekday), minimum duration (default 60, integer 1–1440), optional controlled capability and optional minimum known seats (positive integer). Apply to maximal contiguous gaps; do not bridge breaks, split merely at display-period boundaries or round to slots. Unknown seats do not satisfy a requested minimum; report their exclusion. Capability filter requires the stored token. Inactive rooms are excluded and explained. Invalid filters show labelled errors, retain text and produce no misleading results. Empty/no-window/no-room/all-busy/uncertain states have distinct messages. Filtering is reporting only and does not validate a teaching group's eligibility.

One projection supplies summaries, agenda, filtered gap list and print. Print selected room/week/term/filter basis, generated timestamp, alerts and uncertainty legend on A4 portrait, allowing repeated headings/continued pages without clipped rows. Internal planning output is labelled accordingly, without borrowing a published-version badge as approval. No private teacher/student details beyond existing authorized planning projections. Keep existing publication screen/CSV/print byte/text parity across status changes.

### Interaction and access states

Reuse paper/ink/pine/gold and existing page/form/result components. Desktop has room context, weekly agenda and gap/evidence panels; narrow layouts stack into a seven-day agenda and full-width filters/actions, with no page-wide overflow at 320 px. No horizontal time-grid is required. Include loading, empty, pending, saved, validation, blocked, denied, stale/missing and retry states in review fixtures. Destructive actions remain clearly separated from Edit/Occupancy and return focus to meaningful feedback. Associate errors with controls, focus the result summary, announce pending/results, preserve inputs and distinguish states by text as well as color. Print hides action controls but preserves explanations. [Sketches](mockups/index.html) illustrate representative states with synthetic records only.
