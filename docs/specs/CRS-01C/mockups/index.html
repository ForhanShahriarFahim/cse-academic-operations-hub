CRS-01C review guide

Five sketches of the proposed class-groups workflow. Nothing here is built yet.

What this slice does.

Today only the original import can create a class group, so a newly prepared term can have offerings but nothing that can be scheduled. This slice lets you create a class group for one cohort, or one merged class for several cohorts, give it teachers with workload units and a weekly requirement, and change or remove it later.

Decisions to approve

  1. D-1 Slice boundary. One class group at a time now; “start all class groups from the previous term” is the next slice.
  2. D-2 Editors. System and academic administrators and routine coordinators; everyone else views only. Units affect extra-load eligibility.
  3. D-3 Terms. Draft and active terms are editable; completed terms are read-only. A draft term's groups are scheduled after activation.
  4. D-4 Audience. One course; one or more of its offered cohorts; an offering belongs to at most one class group (no sections yet).
  5. D-5 Teachers and units. Explicit units per teacher; shared classes are “each in full” or “split”, chosen by the editor; a vacancy is allowed.
  6. D-6 Weekly requirement. Meetings per week and weekly minutes for fixed delivery; none for teacher-managed work.
  7. D-7 After first use. Teachers, units and requirement stay editable; audience and removal only while the group has no classes, enrollments, attendance or extra-load records.
  8. D-8 No database change. Rules are enforced in code; reasons and history go to the existing change log.
